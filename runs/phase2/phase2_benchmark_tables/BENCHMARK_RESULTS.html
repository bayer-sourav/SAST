Notes & definitions

Baseline rows (top of table)
Fixed reference values from the PoC publication screenshot (n=27). Not re-run on Phase 2 corpora: Rule-based SAST, CodeQL, Combined (R+CQL).
VDR, FPRR, SRS & PoC success tiers
VDR (vulnerability detection rate) — TP-track recall: fraction of gold-TP cases labeled TP. FPRR (false-positive removal rate) — FP-track recall: fraction of gold-FP cases labeled FP. SRS (security review score) = 1 − (Σ penalty) / (N × 3.0) over all 600 test cases (200 FP + 200 TP + 200 BL gold tracks). Penalties: TP→FP 3.0× CRITICAL · BL→FP 1.5× HIGH · TP→BL 1.0× MODERATE · FP→TP/BL 1.0× ACCEPTABLE · correct label 0× · unlisted transitions 0×. Missing predictions count as 3.0×.

PoC success tiers — all four thresholds (VDR, FPRR, Macro-F1, SRS) must pass simultaneously: EXCELLENT VDR≥0.95 · FPRR≥0.75 · Macro-F1≥0.75 · SRS≥0.93 · GOOD VDR≥0.90 · FPRR≥0.65 · Macro-F1≥0.55 · SRS≥0.80 · MINIMUM VDR≥0.85 · FPRR≥0.50 · Macro-F1≥0.50 · SRS≥0.75. Hard gates → FAIL: VDR<0.85, SRS<0.78, or CRITICAL above limit (>3 on n=27 baselines; scaled to total test size on Phase 2 rows — limit = floor(3×n/27), e.g. >66 when n=600).
Zero-shot
Thinking off · few-shot 0 (fs0). Model sees the v7-balanced prompt only — no in-prompt exemplars.
Few-shot
Thinking off · few-shot 3 (fs3). Three train-split exemplars (TP→FP→BL) appended after the policy block.
Zero-shot (CoT) / Few-shot (CoT)
Same as above with thinking on — chain-of-thought before JSON. Qwen3.5 runs use an 8192-token decode cap.
Stage 2 ship
Phase 2 Stage 2 production cells (v7-balanced prompt, thinking on). Each row is a tuned profile×config from stage2/MANIFEST.json, e.g. 5.9b_fs3_legacy = Qwen3.5-9B · fs3 · legacy 3-shot pack (v2_3shot_tp_2fp).
fs3_legacy / few-shot config tags
v2_3shot_tp_2fp — 3 exemplars (1 TP multi-alert + 2 structural FP). zeroshot — no exemplars (8b_fs0_zeroshot). coder30b_fs3_recall — same fs3 pack, recall-oriented comparison arm.
Macro-F1
Mean of per-track F1 (FP track F1 with positive class FP, TP track F1 with positive class TP). Borderline track excluded from this table.
CRITICAL
Count of gold-TP cases misclassified as FP (missed vulnerabilities on the TP track only). Hard-gate limit: >3 on PoC n=27 total test cases; on the 600-case Phase 2 test, same rate → limit = (3×600)//27 = 66 (fail if CRITICAL>66).
Accuracy
Strict correct labels on FP + TP tracks combined: (correct FP-track + correct TP-track) / 400.
Confusion matrices
Full 3×3 tables (gold TP / FP / BL × predicted TP / FP / BL) over all 600 test cases. Compared cells: Stage 2 GOOD ship cell, Phase 2 MINIMUM-tier matrix cell (same profile/fs3), and Phase 3A LoRA eval. Diagonal counts are gold-correct per track. TP→FP = CRITICAL missed vulns; BL→FP = HIGH over-dismiss; FP→TP = noise kept. Neither Stage 2 GOOD nor Phase 2 MINIMUM predicts BL on BL-gold cases (0/200 diagonal).
Phase 3A LoRA
Qwen3.5-9B fine-tuned with LoRA on 1500 gold-label SFT examples (train split). Eval uses same v7-balanced prompt, thinking on, fs3 as Stage 2. Included in main table when eval summaries exist.
Phase 3B LoRA
Teacher distillation on 1500 train cases · LoRA r=32 · training CSS pick epoch 6 (fs3+CoT val) · ship rerank epoch 4 (fs0_off val). Test rows: fs3 CoT, fs0 direct, and fs0 ship (rerank). Reports: reports/phase3b/ · HTML: runs/phase3/stage3b/benchmark/PHASE3B_BENCHMARK.html.
