    Path injection occurs when a user-supplied string is used to construct a file path for file operations (like `FileOutputStream`).
    Here, `fileName` is constructed from `TESTFILES_DIR` (constant) + `bar` (from user input).
    Since `bar` equals `param` (user input), the full path is determined by the user.
    There is NO sanitization between `bar` and `fileName` regarding path traversal (e.g., no `replace("..")` or validation).
    Also, `fileName` is passed directly to `FileOutputStream`.
    This allows users to specify arbitrary file paths (potentially outside intended directories or overwriting system files).
    This is a classic Path Traversal / Path Injection vulnerability.
    Unlike the XSS case, there is no encoding function wrapping the `fileName` before the file operation.
    Therefore, the sink value (`fileName`) IS attacker-controlled.
    Verdict: **Alert 2 is `alert-TP`**.
