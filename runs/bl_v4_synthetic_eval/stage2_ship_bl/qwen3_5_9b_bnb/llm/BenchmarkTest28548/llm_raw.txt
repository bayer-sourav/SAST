**Alert Details:**
- Rule ID: `java/ssrf`
- Message: "Separate DNS resolution and outbound fetch"
- Sink location: Line 27

**Code Analysis:**

Looking at the code:
```java
@Override
protected void doPost(HttpServletRequest request, HttpServletResponse response)
        throws ServletException, IOException {
    response.setContentType("text/html;charset=UTF-8");
    String param = request.getParameter("BenchmarkTest");
    if (param == null) param = "";
String host = param;
java.net.InetAddress[] addrs = java.net.InetAddress.getAllByName(host);
for (java.net.InetAddress a : addrs) {
    if (a.isSiteLocalAddress() || a.isLinkLocalAddress()) return;
}
java.net.http.HttpClient.newHttpClient()
    .send(java.net.http.HttpRequest.newBuilder(java.net.URI.create("http://" + host)).build(),
        java.net.http.HttpResponse.BodyHandlers.discarding());
    }
}
```

**Data Flow:**
1. User parameter comes in: `request.getParameter("BenchmarkTest")` → stored in `param`
2. `param` assigned to `host` variable
3. `InetAddress.getAllByName(host)` resolves DNS using `host`
4. Loop checks if addresses are site-local or link-local, returning early if they are
5. Finally, makes HTTP request to `"http://" + host`

**Sink Resolution:**
The sink is at line 27: `java.net.URI.create("http://" + host)`

The `host` variable directly receives the user input from `request.getParameter("BenchmarkTest")`. There's no sanitization between the user input and the URI creation.

**SSRF Assessment:**
This IS a legitimate SSRF vulnerability:
1. User input flows directly into the HTTP client URL construction


2. The loop checking for site/local/link local addresses provides minimal protection since attackers could supply external IPs or domain names that resolve to public endpoints
3. The validation fails to block requests to sensitive internal services like metadata servers, databases, or administrative interfaces
4. An attacker could craft payloads targeting localhost, intranet resources, or cloud provider metadata endpoints

**Resolved Sink Value:**
The sink value is `"http://" + host`, where `host` equals the user-supplied parameter. Since this remains attacker-controllable throughout the execution path, the alert represents a true positive.

**Label: TP**

The vulnerability stems from direct concatenation of unsanitized user input into the URI being constructed for the HTTP request.
