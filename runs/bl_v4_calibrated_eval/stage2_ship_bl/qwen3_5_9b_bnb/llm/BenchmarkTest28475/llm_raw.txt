        **Is this exploitable?**
        This is known as a **DNS Rebinding Attack**.
        Scenario:
        1. Attacker sets up a malicious domain `evil.com`.
        2. Initially, `evil.com` resolves to a public IP allowed by the app (e.g., `1.2.3.4`).
        3. The app checks `1.2.3.4` against `isNonPublicAddress`. Since it's public, the check passes.
        4. The app opens a stream to `1.2.3.4`.
        5. Meanwhile, the attacker changes the DNS record for `evil.com` to point to an internal resource (e.g., `localhost` or `192.168.1.1`).
        6. Because the Java client connected to `1.2.3.4` initially, the connection was made to the public IP.
        7. Wait, the vulnerability isn't necessarily DNS rebinding *during* the connection if the connection happens immediately.
        8. The vulnerability arises if the application relies on the *resolved* IP to make decisions but uses the *original* string for the actual request, OR if the attacker can manipulate the DNS resolution time-window.
