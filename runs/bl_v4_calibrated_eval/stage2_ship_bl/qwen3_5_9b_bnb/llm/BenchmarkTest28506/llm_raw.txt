The core issue is that `getAllByName()` can return multiple IPs, and the current check only rejects them if they're marked as non-public. Additionally, even if all returned addresses appear safe, the original hostname itself remains unvalidated against known malicious domains or internal services.

This represents a genuine SSRF vulnerability. The fundamental problem is that user-supplied input flows directly into the URI construction without proper sanitization or domain whitelisting. While the code attempts to validate individual IP addresses, it fails to account for how DNS resolution works—malicious hosts can have multiple records, and blocking just one type of address doesn't eliminate the attack surface.
