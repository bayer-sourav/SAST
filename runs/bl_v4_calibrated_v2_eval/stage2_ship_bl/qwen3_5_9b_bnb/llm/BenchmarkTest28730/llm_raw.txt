    -   Wait, let's look closer at the logic.

    -   Vulnerability Type: Open Redirect.

In a browser context, users can navigate to a page with a custom referer (though modern browsers restrict some things, it's generally considered a vector for open redirects if the application trusts the Referer header blindly).

    -   The fact that the Referer check acts as a *gatekeeper* for *whether* the redirect happens doesn't sanitize the *destination*.
    -   Standard Path Injection/Open Redirect definition: Using user-supplied input in a URL redirect without validating that the destination is within allowed boundaries.
    -   Here, `param` is used directly. There is no whitelist/validation of `param`.
    -   Therefore, this is a classic Open Redirect vulnerability triggered by the presence of the Referer header check combined with direct usage of user input in `sendRedirect`.
