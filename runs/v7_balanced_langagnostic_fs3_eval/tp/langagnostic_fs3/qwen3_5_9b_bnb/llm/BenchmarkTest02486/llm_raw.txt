**Is this sufficient mitigation?**

The question is whether replacing the last character prevents XSS.
An attacker could inject malicious script tags like `<script>alert('xss')</script>`.
If they send: `<script>alert('xss')</script>Z` (adding a trailing Z to satisfy length > 1 condition), the output would be `<script>alert('xss')</script>Z`.

Condition `M > 1` is true.
Last character is replaced with "Z".
Result: `<script>alert('xss')</script>Z` (assuming the last char wasn't already Z, or just replaced).
Wait, if the input ends with something else, it gets replaced by Z.
But the rest of the payload remains intact!
So `<script>alert('xss')</script>` becomes `<script>alert('xss')</script>Z` (if the last char was not Z).

Crucially, the script tag structure is preserved. The browser will interpret `<script>` as executable code.
Replacing the very last character with "Z" does **NOT** neutralize the XSS payload embedded within the string. The payload is typically much longer than 1 character.
