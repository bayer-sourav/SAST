**Alert 1: `java/insecure-randomness`**
- **Rule ID**: `java/insecure-randomness`
- **Message**: Potential Insecure randomness due to a [Insecure randomness source.](1).
- **Sink**: Line 96 (`rememberMeKey`).
- **Source Flow**: `nextGaussian(...)` -> `toString(...)` -> `substring(...)` -> `rememberMeKey`.
- **Analysis**:
    - The source is `new java.util.Random().nextGaussian()`.
    - `java.util.Random` is known to be cryptographically weak. Its seed is typically derived from the current time or process identifier, making it predictable within short intervals.
    - The generated value is converted to a string and trimmed to become `rememberMeKey`.
    - `rememberMeKey` is used as the value for a session cookie (`rememberMe`). Session cookies are security-sensitive material (used for authentication/session management).
    - Using a weak PRNG like `java.util.Random` to generate session tokens or secrets is a classic vulnerability (insecure randomness).
    - Is there any mitigation? No. The value flows directly from the weak RNG to the sensitive location (cookie value).
    - Verdict: **alert-TP**. This is a real vulnerability. Weak randomness feeding a session token is exploitable (session fixation/prediction attacks).
